# 《砰！爆米花失控了》游戏设计方案

> **英文名暂定：** POP! Popcorn Overload  
> **类型：** 3D 卡通增量 / 轻放置  
> **平台：** 网页（Web），不做桌面版  
> **核心承诺：** 从灶台上的一粒玉米开始，一路爆到全世界下爆米花雪，最后发现月亮也是一粒玉米。

> **二期变更（试玩反馈后，优先于下文）：** 游戏定位偏挂机、偏娱乐。生产单位增至 10 代，每代产量大幅跃升；一周目约 2.5 小时，开局大幅提速，累计产量到约 10 亿亿量级。按住鼠标可连续爆，不点击也能通关。画面方向定为精致微缩模型。具体目标见 `EXECUTION_PLAN.md` 第 12 节，实际数值以 `BALANCE.md` 为准。
>
> **六期变更（优先于下文和二、三期）：** 升级从 120 项合并成 4 栏共 36 档：手艺（点击、金色玉米、按住、自动搅拌）、产线（每个场景一档联动、一档金色产线）、玩法（大炮、跳跳粒、离线）、装修（10 件）。每栏只摆出下一档，买下后原地换成下一档。每种设备的四档升级改成里程碑，台数够了自动生效：10 / 25 / 50 / 75 / 100 台时每台产量 ×1.75 / ×2 / ×4 / ×2 / ×2，之后每 50 台再 ×2。口味仍是独立的一栏 12 档。见 `EXECUTION_PLAN.md` 第 16 节。

---

## 1. 为什么换成爆米花

原方案的结构是对的：要有明确产物、明确生产动作和自然的自动化阶梯。问题在于纸飞机的折叠偏安静，飞出去之后也很难产生“堆满了”的满足感。

| 对比项 | 纸飞机 | 爆米花 |
|---|---|---|
| 核心动作 | 折叠、放飞，偏舒缓 | 玉米粒鼓胀后“砰”地炸开，自带爆发 |
| 产物变化 | 纸变成飞机 | 小硬粒瞬间膨胀成一大朵，变化夸张 |
| 增长画面 | 天空里的飞机变多 | 从锅里溢出，淹没厨房、影院和城市 |
| 声音 | 纸张声较弱 | 噼啪声从零星变成密集轰鸣 |
| 搞怪空间 | 有限 | 爆米花雪、天气预报、月亮玉米粒 |
| 程序化 3D | 容易 | 容易，几种团块形状即可实例化 |

**一句话玩法：点一下，砰一朵；买机器，砰一屋；最后砰掉整个世界。**

## 2. 设计边界

### 目标

1. 第一分钟就能看懂：点玉米，爆开，数字增长。
2. 每次点击都有“蓄力、爆发、落地”的完整反馈。
3. 每次重要购买都能在场景里看见。
4. 爆米花堆的高度和声音本身就能表达进度。
5. 内容少而精，靠动效和尺度变化形成丰富感。

### 明确不做

- 不做股市、季节活动、宠物、装备和小游戏合集。
- 不做多层转生和复杂遗产树。
- 不做角色骨骼动画，人物只以手、影子或玩具小人出现。
- 不为每一粒爆米花做真实刚体物理。

## 3. 核心循环

**10 秒循环：** 点击锅中玉米 → 玉米发抖鼓胀 → 砰地炸开 → 爆米花落到堆上 → 数字增长。

**1 分钟循环：** 手动爆 → 买设备 → 设备开始自动爆 → 买口味升级 → 爆米花变色、产量上升。

**长期循环：** 堆满当前场景 → 溢出突破 → 镜头拉远 → 新场景和新设备 → 全球爆米花雪 → 月亮结局。

**只有一种资源：爆米花。** 它既是分数也是货币。购买时，一只大铲子从堆上铲走相应的量，让“花钱”也有画面。累计产量决定阶段，因此花费不会让进度倒退。

```text
每秒产量 = Σ(单位数量 × 基础产量 × 里程碑倍率) × 1.4 ^ 口味升级数
点击产量 = 1 + 每秒产量 × 1%
下一台价格 = 基础价 × 1.15 ^ 已拥有数量
```

## 4. 生产单位

| 顺序 | 单位 | 基础价 | 基础产量/秒 | 场景表现 | 搞怪点 |
|---:|---|---:|---:|---|---|
| 1 | 小奶锅 | 15 | 0.2 | 灶台上多一口抖动的小锅 | 锅盖总被顶飞 |
| 2 | 爆米花推车 | 200 | 1.5 | 红白条纹小车，玻璃柜里不断翻滚 | 车轮被爆米花淹没 |
| 3 | 老式爆米花炮 | 4,000 | 10 | 黑色铁炉转动，定时开炮 | 每炮都吓飞一群鸽子 |
| 4 | 影院爆米花机 | 8 万 | 60 | 大玻璃柜和传送带 | 观众只来吃，不看电影 |
| 5 | 焦糖工厂 | 200 万 | 400 | 烟囱喷出焦糖色云朵 | 下班时全城都很香 |
| 6 | 火山炉 | 6000 万 | 2,800 | 火山口持续喷发爆米花 | 地质学家放弃解释 |

单位拥有 25、50、100 个时产量 ×2，之后每 50 个再 ×2。里程碑要在模型上体现，比如多一个炉口、换一块招牌、加快转速。

## 5. 升级

**口味升级（12 级）：** 每级产量 ×1.4，价格 = 300 × 4^(已购数量)。每级都改变爆米花外观，这是最直接的“买了就看见”。

黄油 → 海盐 → 焦糖 → 草莓 → 抹茶 → 巧克力 → 芝士 → 辣椒 → 彩虹 → 星空 → 黄金 → 神秘味道

**点击升级：** 一次点击炸开更多粒，粒数从 1 增加到 3、5、10，点击的画面也随之变大。

**协同升级：** 只做少量有画面的组合。例如推车给影院供货时，两者之间出现一条小传送带。

## 6. 招牌技能：大炮“砰！”

玩家**按住**摇动老式爆米花炮，压力表上升；指针进入绿区时**松手**开炮。

| 项目 | 初值 |
|---|---|
| 普通收益 | 立即获得 30 秒产量 |
| 绿区收益 | 立即获得 60 秒产量 |
| 蓄力时长 | 约 1.2 秒 |
| 绿区宽度 | 约 160 毫秒，可用升级放宽 |
| 冷却 | 90 秒 |
| 过压 | 炮盖崩飞，只得 10 秒产量，但有一段搞笑动画 |

过压不算严重惩罚，因为搞砸也应该好笑。

**唯一的随机事件：跳跳粒。** 每 2～4 分钟有一粒玉米从堆里蹦出来乱跑，点中后 20 秒内产量 ×5。

## 7. 场景和进度

| 阶段 | 场景 | 突破门槛（累计） | 活跃玩家目标时间 | 突破画面 | 奖励 |
|---:|---|---:|---:|---|---|
| 1 | 灶台 | 1,000 | 约 3 分钟 | 锅盖飞起，爆米花涌出 | 解锁大炮 |
| 2 | 厨房 | 5 万 | 约 12 分钟 | 冰箱门被顶开，窗户炸出 | 解锁影院机线索 |
| 3 | 电影院 | 1000 万 | 约 35 分钟 | 银幕被撑破，观众被冲出门 | 解锁焦糖工厂 |
| 4 | 小城 | 10 亿 | 约 80 分钟 | 街道变成爆米花河，电视播报灾情 | 解锁火山炉 |
| 5 | 地球 | 200 亿 | 约 150 分钟 | 全球下爆米花雪 | 进入结局 |

**贯穿伏笔：** 第 1 阶段窗外的月亮偶尔轻轻抖一下，越往后抖得越明显。

**结局：** 地球全白后，月亮开始发烫、鼓胀。画面安静一拍，然后巨大的“砰”，月亮变成一朵爆米花。一只宇宙尺度的手伸进画面，抓走了地球。

**可选的通关后内容：** “再来一锅”重置本轮，保留口味图鉴，获得永久小幅加成，并解锁一种锅的外观。首个可玩版本不做。

### 镜头规则

- 平时镜头稳定，只有突破时拉远。
- 突破演出约 2.5 秒，可跳过。
- 旧场景要变成新场景里的小物件，让尺度变化连贯。
- 提供“减少镜头运动”选项。

## 8. 画面风格

### 定位：复古糖果色的玩具微缩世界

像一套做工精致的 1950 年代影院主题玩具：圆润、光亮、色彩饱满，全部由程序化 3D 生成，不依赖外部模型。

- **主色：** 奶油白、黄油黄。
- **强调色：** 影院红、薄荷绿、天空蓝。
- **渲染：** 三阶卡通明暗、柔和边缘光、珐琅玩具高光，主体使用干净描边。
- **爆米花：** 用 5～6 种不规则团块，表面由程序位移生成，中心带一点焦黄。
- **界面：** 影院票根、霓虹灯牌和爆米花桶，数字用胖圆体，以万、亿显示。

### 主要风险与对策

白色爆米花堆容易糊成一片。要用环境遮蔽、顶部暖光、底部冷影和少量深色焦点强化层次，并在原型阶段优先验证。

### 画质优先级

1. 单朵爆米花和炸开瞬间的造型。
2. 锅和堆之间的接触阴影。
3. 堆的层次与落地动态。
4. 场景构图和色彩。
5. 背景细节。

## 9. 动效设计

| 事件 | 动画链 | 时长 |
|---|---|---:|
| 点击 | 玉米压扁发抖 → 鼓胀发亮 → 停顿约 40ms → 炸开 → 弹起旋转 → 落堆 → 周围晃动 → 数字跳动 | 0.25～0.45 秒，点击立即响应 |
| 自动生产 | 设备抖动 → 喷出一簇 → 汇入堆 → 计数流动 | 0.4～0.8 秒 |
| 购买单位 | 卡片下压 → 铲子铲走爆米花 → 设备落下回弹 → 立刻爆第一批 | 0.6～1.0 秒 |
| 口味升级 | 调料瓶飞入 → 摇撒 → 颜色从落点向全堆扩散 | 约 1 秒 |
| 大炮 | 炉子加速 → 压力表颤动 → 松手 → 炮口冲击波 → 爆米花喷泉 → 数字猛涨 | 蓄力约 1.2 秒，爆发约 1 秒 |
| 阶段突破 | 边界开裂 → 声音收紧 → 静默半拍 → 爆发涌出 → 拉远 → 新场景定格 | 约 2.5 秒 |

### 动效原则

- 输入必须当帧响应，动画不能挡住连续点击。
- 强度分级：小收益轻响，大收益才震屏，闪光只留给关键时刻。
- 高产量时不再逐粒播放，改成爆米花喷泉和连续粒子流。
- 所有长演出都可加速或跳过。

### 声音

- 手动点击：清脆的“啵”，音高小幅随机。
- 产量上升：单声 → 噼啪 → 密集爆裂 → 雨声般的白噪音 → 低频轰鸣。
- 同时播放限制在 8～12 个声部，其余并入循环层。
- 大炮、突破和结局有专属声音。
- 需要使用授权音效，并由真人试听调整。

## 10. 数值与节奏

以下数值来自简化脚本模拟。脚本假设活跃玩家每秒点 3 次、每 90 秒用一次普通大炮，挂机玩家每秒点 0.5 次、不用大炮，并按贪心策略购买。它尚未计入点击升级、绿区收益、跳跳粒、协同和离线收益。

| 时间 | 活跃玩家累计 | 挂机玩家累计 |
|---:|---:|---:|
| 3 分钟 | 约 1,300 | 约 210 |
| 12 分钟 | 约 5.8 万 | 约 6,300 |
| 35 分钟 | 约 900 万 | 约 100 万 |
| 80 分钟 | 约 9.7 亿 | 约 1.3 亿 |
| 150 分钟 | 约 220 亿 | 约 50 亿 |

**已知问题：** 模拟中最长购买等待，活跃玩家约 4.6 分钟，挂机玩家约 6.5 分钟，超过目标。需要用阶段奖励、协同升级和点击升级填补 35 分钟之后的空档。

**验收目标：**

- 10 秒内完成第一次爆开。
- 1 分钟内买到第一个自动单位。
- 前 20 分钟每 30～60 秒有一次有意义的购买。
- 活跃玩家全程等待不超过 3 分钟。
- 主线约 2.5～4 小时。

**离线收益：** 初值为产量的 25%，上限 8 小时，试玩后调整。

## 11. 技术方案

| 模块 | 方案 |
|---|---|
| 3D | Three.js + WebGL2 |
| 语言与构建 | TypeScript + Vite |
| 界面 | HTML/CSS，与 3D 画布分离 |
| 动画 | 自写弹簧和时间曲线 |
| 音频 | Web Audio，首次点击后加载 |
| 存档 | IndexedDB，使用带版本号的 JSON 结构 |

### 三层结构

- **模拟层：** 只处理资源、价格、升级、成就和离线收益，不依赖渲染，可在 Node 中做数值模拟和测试。
- **事件层：** 发出 `kernel_popped`、`producer_purchased`、`flavor_unlocked`、`cannon_fired`、`stage_broken`。
- **表现层：** 响应事件，可合并高频事件，但不能影响经济结果。

### 爆米花渲染分级

| 层级 | 数量 | 表现 |
|---|---:|---|
| 飞行近景 | 约 100～200 | 独立的弹道、旋转和落地挤压，使用简化碰撞 |
| 堆表面 | 约 3,000 | `InstancedMesh`，贴合堆的高度场，附近受冲击时晃动 |
| 堆主体与远景 | 不随产量增长 | 高度场网格加噪声着色器，远看连成起伏地形 |
| 爆米花雪 | 固定粒子上限 | GPU 粒子循环 |

画面数量是产量的视觉映射，不是真实库存。堆高按累计产量的对数增长，每阶段在突破前接近填满。

### 性能与存档

- 常见集成显卡 1080p 目标 60 FPS，低画质不低于 30 FPS。
- 帧率不随累计产量持续下降。
- 自动调整分辨率、实例数量和阴影质量。
- 每 30 秒及重要事件后自动保存，支持导入导出，存档结构带迁移版本。

## 12. 制作顺序

### 第一步：60 秒手感原型

一口锅、一个灶台、玉米粒炸开、堆积、计数、声音和一个小奶锅。

**通过标准：** 连续点一分钟仍然觉得爽，白色爆米花看起来可口而不是一团糊。

### 第二步：垂直切片

3 个单位、4 级口味、大炮、灶台到厨房的突破、存档和离线收益。

**通过标准：** 试玩 15 分钟后，玩家想知道下一个场景是什么。

### 第三步：完整内容

6 个单位、12 级口味、5 个场景、约 20 个升级、20～30 个搞怪成就、月亮结局。

### 第四步：发布打磨

低配和浏览器兼容、长时间运行、音频混音。

## 13. 决策摘要

| 项目 | 决策 |
|---|---|
| 主题 | 爆米花生产失控 |
| 核心产物与资源 | 爆米花 |
| 核心动作 | 点击玉米，鼓胀后炸开 |
| 自动化 | 6 类生产单位 |
| 主要升级 | 12 级可见口味 |
| 主动技能 | 老式爆米花炮，按住蓄压，松手开炮 |
| 场景 | 灶台 → 厨房 → 电影院 → 小城 → 地球 |
| 结局 | 月亮爆开 |
| 画面 | 复古糖果色玩具微缩世界，程序化 3D 卡通 |
| 引擎 | Three.js + TypeScript + Vite |
| 第一任务 | 60 秒手感原型 |

**最终原则：把“鼓起来、砰、堆起来、溢出去”这条体验链做到极致。**
