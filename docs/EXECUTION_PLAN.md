## 1. 成品定义

全部满足才算完成：

1. 从第一粒玉米玩到月亮结局，无阻断 bug，主线约 3 小时（活跃玩家）。
2. 内容完整：6 个生产单位、12 级口味、5 个场景、约 20 个功能升级、大炮、跳跳粒、24 个成就、结局、通关后的“再来一锅”。
3. 纯网页交付，不做桌面版；存档可在不同浏览器之间导入导出。
4. 开始界面、暂停、设置、存档管理、结局字幕齐全，没有占位内容。
5. 通过第 7 节的全部质量门。

**不在本计划内：** 桌面版与安装包、Steam 上架、线上部署、商业素材采购。后三项是对外操作，需要你另行确认。

### 关于“顶级水准”

我会按顶级标准制作和验收，但有三件事不能由我单独证明：

| 事项 | 限制 | 处理方式 |
|---|---|---|
| 手感是否上头 | 我无法亲身操作感受 | 调参面板、录屏逐帧检查、你在 3 个试玩点反馈 |
| 声音是否好听 | 我听不到 | 用波形和响度检查技术质量，听感由你判断 |
| 低配真机表现 | 本机是 RX 7900 XT，无法代表集成显卡 | 用降分辨率和压力场景估算，真机测试列入发布前清单 |

## 3. 工程结构

```text
src/
  sim/            纯逻辑：状态、经济、升级、技能、成就、离线、存档结构
  content/        数据表：单位、口味、升级、场景、成就、文案
  events/         类型化事件总线
  render/
    core/         渲染器、相机、画质分级、后处理
    materials/    卡通、珐琅、爆米花、堆积着色器
    geometry/     程序化模型：爆米花、锅、设备、场景
    popcorn/      飞行粒、堆表面实例、高度场、雪
    scenes/       5 个场景及切换
    fx/           冲击波、蒸汽、碎屑、数字
  motion/         弹簧、缓动、时间线、顿帧、屏震
  audio/          音频图、声部池、产量分层
  ui/             HUD、商店、设置、成就、结局
  platform/       Web 存档与窗口适配
  debug/          调参面板、作弊、性能浮层（发布构建剔除）
tools/            数值模拟、截图、性能测试
tests/            单元测试和端到端测试
docs/             设计、平衡记录、试玩记录、素材授权
```

**硬规则：**

- `sim/` 不得引用 `render/`、`ui/`、`audio/` 或浏览器 API。
- 模拟固定每秒 10 步；渲染只读状态和事件，不能修改经济结果。
- 所有可调数值集中在 `content/` 或动效配置中，不散落在逻辑里。
- 动画不阻塞输入，任何演出都不能吞掉点击。

## 4. 里程碑

### M0 工程地基

- 在新工作目录中放入本计划（`docs/EXECUTION_PLAN.md`）和设计方案。
- 初始化 git、Vite、TypeScript 严格模式、Vitest、Playwright。
- 搭好目录、事件总线、固定步长循环、渲染循环、调试面板、性能浮层。
- 建立截图脚本：可按指定场景、时间和产量输出固定画面。

**验收：** 构建、类型检查、测试全部通过；空场景 60 FPS；截图结果可复现。

### M1 “一粒玉米”手感原型（最重要）

- 程序化生成玉米粒、6 种爆米花团块、小锅、灶台。
- 卡通材质、主光与环境光、接触阴影、基础后处理。
- 完整点击链：压扁 → 发抖 → 鼓胀 → 顿帧 → 炸开 → 飞行 → 落堆 → 周围晃动 → 数字跳动。
- 爆米花堆：高度场 + 表面实例，落点隆起。
- 合成音效第一版，连续点击时音高变化。
- 计数器和第一个单位“小奶锅”。

**验收：**

- 点击到首个视觉变化不超过 1 帧。
- 每秒 10 次点击时动画不断裂、无掉帧。
- 单朵爆米花近看好看，堆积近看不糊。
- 录屏逐帧检查无穿帮、闪烁和跳变。
- **试玩点 A：把版本交给你体验手感。** 我继续推进不依赖手感的工作，收到反馈后优先修正。

### M2 经济核心

- 实现全部单位、口味、升级、里程碑、跳跳粒和大炮的逻辑。
- 实现离线收益和带迁移版本的存档。
- 升级 `tools/simulate`：模拟点击型、挂机型、大炮熟练型三类玩家，把全部系统计入。
- 修复当前已知问题：35 分钟后最长等待约 4.6 分钟。

**验收：**

- 单元测试覆盖价格、倍率、离线、存档迁移。
- 活跃玩家到达各阶段约 3、12、35、80、150 分钟，偏差不超过 20%。
- 活跃玩家最长等待不超过 3 分钟，挂机型不超过 5 分钟。
- 6 个单位都有购买价值，不出现长期无人购买的单位。

### M3 界面与反馈系统

- 票根风格商店、霓虹数字、升级卡片、压力表、成就提示。
- 按钮按压回弹、可买状态提示、批量购买、中文大数显示。
- 铲子购买动画、口味撒料和全堆变色。
- 强度分级系统：统一管理顿帧、屏震、闪光和声音上限。

**验收：** 1280×720 到 4K 布局正确；不看说明也能完成第一次购买；数字长度变化不造成界面跳动。

### M4 垂直切片

## 5. 画面规格

**目标观感：** 灯光精致的复古糖果色玩具摄影，而不是低模素材拼接。

| 项目 | 规格 |
|---|---|
| 明暗 | 三阶卡通渐变，叠加柔和环境遮蔽 |
| 描边 | 主体用反向外壳，粗细随距离调整；堆积物不描边 |
| 爆米花 | 半透感模拟、奶油高光、焦黄核心，5～6 种造型随机旋转缩放 |
| 光照 | 暖色主光、冷色补光、边缘光，每个场景单独调色 |
| 后处理 | 色调映射、轻微暗角、仅高亮处小范围泛光 |
| 配色 | 每个场景一个主色，爆米花始终是最亮的视觉中心 |

**场景要求：** 每个场景至少包含一个一眼可辨的轮廓、三层景深、一个持续运动元素和两个搞怪细节。

**审查方法：** 固定视角截图，分别检查原图、缩略图和灰度图。主体轮廓在灰度和缩略图中仍要清楚。

## 6. 动效规格

默认值放入调参面板，以试玩结果为准。

| 参数 | 初值 |
|---|---:|
| 点击压扁 | 80ms，纵向 0.75 |
| 炸开前顿帧 | 40ms（连点时自动缩短到 0～20ms） |
| 炸开膨胀 | 90ms，过冲 1.25 倍后回弹 |
| 落堆挤压 | 120ms，影响半径约 3 朵 |
| 数字跳动 | 100ms，放大 1.08 倍 |
| 普通屏震 | 不触发 |
| 大炮屏震 | 约 250ms |
| 突破静默 | 约 300ms |

**统一规则：**

1. 每个效果的结束状态都是下一个效果的开始状态。
2. 不做瞬移和硬切，例外只有刻意的喜剧切镜。
3. 同一时刻只有一个视觉主角。
4. 小事件克制，把最强的屏震和闪光留给大炮、突破和结局。
5. 尊重“减少动态效果”设置。

## 7. 质量门

| 类别 | 标准 |
|---|---|
| 性能 | 本机 4K 稳定 60 FPS；低画质压力场景的帧时间预算不超过 16.6ms；帧率不随累计产量下降 |
| 渲染量 | 绘制调用不超过 150；实例上限固定 |
| 体积 | 首屏资源目标不超过 8MB（不含音频），以构建结果为准 |
| 稳定性 | 控制台无错误；2 小时压力运行无持续内存增长 |
| 存档 | 旧版本迁移、损坏恢复、导入导出均有测试 |
| 数值 | 三类模拟玩家都能通关；无超过上限的等待；结果写入 `docs/BALANCE.md` |
| 画面 | 全部场景通过原图、缩略图、灰度图审查 |
| 动效 | 所有主事件逐帧检查无穿帮 |
| 体验 | 3 个试玩点的问题全部关闭，或明确记录为不修改及原因 |
| 文案 | 无占位、无错别字、笑点不重复 |

**日常命令：**

```text
npm run dev
npm run check      类型检查 + 单元测试

npm run shots      生成审查截图
npm run e2e        端到端测试
npm run build      Web 构建
```

CI 不在本计划内。本地 `check` 控制在 1 分钟内，完整验证控制在 5 分钟左右。

## 8. 风险与预案

| 风险 | 预案 |
|---|---|
| 爆米花堆糊成白块 | M1 优先攻克；调整遮蔽、色温和表面实例密度 |
| 程序化场景显得简陋 | 收窄为微缩玩具风格，少而精；M4 不达标不铺内容 |
| 点击很快后变得重复 | 连点节奏、音高、暴击式大爆开、点击升级改变表现 |
| 中后期无聊 | 模拟控制等待，每阶段引入新画面和新操作目标 |
| 音频质量不足 | 换用授权素材；你试听后定稿 |
| 低配设备性能差 | 固定实例上限，分级降质，发布前真机测试 |
| 依赖版本不兼容 | 退到兼容版本并记录 |
| 内容范围膨胀 | 不新增系统；新想法进入 `docs/BACKLOG.md`，成品后再议 |

## 14. 四期：旗舰打磨与上线

三期收尾时的只读核对发现以下问题，四期围绕它们展开。原则是少而准：每一项都有事实依据和可测的验收标准，覆盖建模、动效、前端、动画、性能五个方面。做完后创建 GitHub 仓库，部署到 GitHub Pages，并在线上真实测试。以下目标优先于前文。

**依据：**

1. 4 个成就拿不到：`poke-first`、`poke-100`、`egg-first`、`egg-all` 依赖的 `Simulation.poke()` / `findEgg()` 在游戏里没有调用方，彩蛋图鉴也没有界面。
2. 三期唯一没达标的性能门：4K 极高画质下厨房、地球 p99 为 25–31ms。

## 15. 五期：视觉旗舰

四期上线后的要求：下一轮集中做表现层，包括建模精细度、整体场景、动画衔接、场景动效、视觉反馈、视效、光影和质感，往更美观、更精致的方向全面迭代。不改数值和玩法规则。以下目标优先于前文。

**依据：**

1. 光照：反光只是三色渐变加解析灯箱（`materials/glsl.ts` 的 `envColor`、`studioSoft`），环境光是两色半球；没有环境探针，铬和搪瓷照不出房间。
2. 质感：焦糖口味的爆米花堆在小城看起来像碎石；玉米粒像橙色水滴；丝绒幕布和座椅像塑料；星球大陆是 3 层低频噪声，糊成色块，海面没有太阳高光，太空背景是平涂。
3. 建模：电影院前排观众是一个球加一个胶囊，座椅是 3 个盒子；小城的树是一团球，车很简单；火山炉在四期没有改；灶台背后的大红锅盖读起来像一个红圆盘；锅内壁是平涂的深蓝。
4. 动效与反馈：游戏中镜头完全静止（只有标题页会漂）；粒子没有光照，和几何体相交处有硬边；树、旗、幕布不会动；悬停只是把设备抬起；连击每 12 次只有一种爆发。
5. 帧时余量：4K 极高画质纯渲染 p99 为 6.4–9.4ms，60Hz 下 0 掉帧（四期阶段 6）。

**已确认：** 画风保持复古糖果色玩具微缩，质感往讲究的实物微缩摄影靠（保留配色和卡通分层，加入真实的环境反射、透光、布料光泽）；绘制次数仍守 120（硬上限 150），**三角形上限 1000 万 → 1300 万**，以 4K 60Hz 实测 0 掉帧为准；三项延后的展示功能都做（购买飞入、连击分级视效、拍照模式，只改表现，不改数值）；做完后推送、部署到 GitHub Pages 并做线上验证。
